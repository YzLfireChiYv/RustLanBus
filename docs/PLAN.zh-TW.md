## 目的與完成邊界

把若干區域網路電腦上的原始音訊匯集到一台連接耳機或揚聲器的 Windows 電腦。保留擷取時可獲得的有效 PCM 精度，並盡量降低可避免的延遲。必要的時鐘校正、混音與目標揚聲器適配，是播放中的明確組成部分。沒有固定的毫秒目標。

原始碼透過共享控制器連接已約定的功能。2026-10-26 的收尾工作包括生效設定套件與遷移、卡片的增刪改查、按路由如實反映狀態、閒置時關閉擷取、資源退役、平滑的增益/復原邊界，以及同時使用的 IPv4/IPv6 路徑。有針對性的編譯支援實作；所有者執行全部實際的啟動、介面、音訊與網路測試。目前任何建置或封存都不能確立整套產品完成。歷史封存早於本批更新。

## 應用程式結構

- Tauri 2 提供 Windows 桌面外殼、視窗與系統匣。React 19 與 TypeScript 在已安裝的 Microsoft Edge WebView2 執行環境中彩現本機介面。不需要託管網站。
- Rust 負責組態、房間、規則、擷取、傳輸、時鐘與播放。音訊緩衝區不經過 JavaScript。
- 桌面與正式的無介面 CLI 使用同一個 `RunningParticipant` 控制器與同一套命令。一份設定對應一個正在執行的 GUI 或 CLI 執行個體。CLI 不遠端控制已經開啟的桌面。
- 擷取、網路送達與播放目標擁有各自獨立的所有權。每個已解析的輸出裝置有一個播放執行單元與一個時鐘。

## 約定的目標行為

### 房間與成員

- 一個活動房間支援多名獨立成員。每台裝置提供自己的名稱，加入期間名稱固定。
- Windows 建立者或 OpenWrt 服務提供房間目錄與對等端位址。Windows 建立者離開或切換房間時，停止自己的聯絡服務。沒有主持端權限矩陣、踢出/審批層或自動主持端遷移。
- 密碼防止誤入。音訊方向是直接 P2P。聯絡服務中斷後，已經建立的直接音訊繼續，目錄復原在背景進行。
- 已儲存的卡片與已探索的房間彼此分開。首先選擇唯一的精確名稱。名稱重複時，明確輸入的 IP 能唯一符合則使用該 IP，否則由使用者選擇。沒有探索到該名稱時，對輸入的位址進行探測，返回的名稱必須符合。嚴格的自動進入要求輸入的名稱與 IP 相互對應。
- 直接位址若回報另一個房間名稱，這是需要糾正的目標錯誤。背景等待只提供給暫時缺席或聯繫失敗。自動組網同時繫結兩個位址族，並保持每條對等路徑中健康的那一條。嚴格限制網路介面或明確位址時，不會悄悄改走其它路徑。明確繫結到迴路的工作階段預設進入本機位址輸入，不進行區域網路瀏覽。探索失敗不會中止可用的 TCP 目錄；探索會獨立復原。明確的探索覆寫保留其所提供的範圍。
- 成功加入未知房間會儲存一張卡片。探索從不會填入已省略的已儲存 IP。再次開啟時復原已儲存的房間意圖。明確 Leave 停用自動再次進入。

### 音源與方向

- 沒有接收端、也沒有本機監聽時，實際的原生擷取會關閉，同時保留對等控制、keepalive 與發佈意圖。已有的訂閱會喚醒擷取，無需等待新的連線。
- 系統聲音與麥克風是相互獨立的原始音源。預設：系統發佈開，麥克風發佈關，本機監聽關。
- 系統聲音是對所選播放端點的迴路擷取，該端點通常是已安裝的虛擬揚聲器。單獨的實體輸出承載本機監聽與接收到的音訊。RustLanBus 引導設定，不提供自訂核心驅動程式。
- 預設規則允許向所有人傳送，並且不從任何人接收。從 A 到 B 需要 A 允許傳送，並且 B 選擇接收。未選擇的方向不傳送音訊。
- 收聽一名成員時，覆蓋該成員目前與之後的音源。展開的控制項可以關閉某個音源角色。本機監聽獨立於房間成員身分。普通用戶端所發佈的內容限於本機原始音訊。

### 規則與持久化

- 可編輯的 JSON 存放全域規則，以及每個房間一份設定檔。全域規則先執行，房間規則隨後執行。較後的符合賦值按每個已指定欄位分別覆蓋。
- 條件明確比對名稱、IP 或兩者。僅按名稱的操作會影響所有同名裝置。不會推斷 IP 或持久裝置身分。
- 房間操作更新並儲存房間規則。音源方向、輸出目標與部分混音欄位保持同一明確範圍。
- 介面顯示決定性規則的來源，以及每個檔案的已儲存、待處理、外部變更與寫入失敗狀態。外部取代予以保留。重新載入會套用檔案編輯。無未儲存改動的全域規則在進入房間時也會重新讀取。
- 卡片可透過共享所有者編輯與刪除，並帶有外部變更的修訂檢查；目前活動卡片必須先離開。
- 一份可讀的 JSON 設定套件匯出目前生效的本機/全域/房間值，包括尚未儲存的改動。明確的還原/複製匯入會預覽取代內容，檢查來源與目標修訂，並保留一個復原目錄。複製會建立新身分，清除本機音訊/網路繫結，並關閉自動進入、監聽與登入意圖；Main 路由保留，固定目標被移除並列出讓你重新指定，僅含固定目標的路由保持為空。
- 未儲存的全域規則在房間切換之間保持有效，直到明確重新載入。離開或切換房間時，在可見警告之後捨棄未儲存的房間變更。匯出可以救出尚未儲存的值，且不改寫它們的原檔。明確結束會標出尚未儲存的檔案，並提供返回或捨棄。

### 格式、播放與輸出

- 原生整數 PCM16/24/32 與 F32/F64 共用一套精度與揚聲器遮罩描述子。傳輸保留所宣告的原始表示。工作取樣使用 F64。目前媒體線路：RLC5/RLP5。目錄 JSON version2 在同一 UDP 連接埠上攜帶有界的位址備選。目錄實作與回傳實作都需要與用戶端一併更新。更早的開發中對等端需要一併更新。
- 支援單聲道、立體聲以及常見的 5.1/7.1 佈局。Microsoft 已發布的係數在現有渲染器中適配受支援的目標。不受支援的組合按音源/輸出回報問題，原始傳輸與其它輸出繼續。
- 每個音源可以送往多個輸出。`main` 跟隨所選的主裝置。固定端點選擇保持固定。缺失的固定裝置等待復原，不進行回退。同一端點的別名只渲染一次。
- 每個輸出顯示自己的音源階段、裝置/格式錯誤、電平與過載。已提交/正在執行的指示描述軟體進度；它不聲稱硬體已經發出可聽見的聲音。介面更新缺失或過期時可見。
- 已脫離的完整 DSP 通道在冷控制邊界退役。短暫的增益/靜音/復原斜坡共用現有渲染器，不增加延遲的 PCM 佇列。
- 共用一個輸出的音源在該輸出上混音。次級控制項提供音源增益、靜音、獨奏、聲像與主音量，並帶有電平與過載資訊。選用限制器預設為關。錯過的舊音訊被丟棄，復原之後回到目前聲音。

### 介面、CLI 與 Windows 整合

- 房間與成員是首要內容。音源詳情、輸出路由、混音、規則與診斷是次要內容。首次使用包含本機組態與音訊路由引導。
- 一般視窗帶有工作列按鈕。關閉會隱藏視窗，應用程式繼續執行。系統匣恢復視窗並提供「退出」。明確選擇「退出」停止背景執行單元。
- 正式 CLI 覆蓋組態建立與檢查、房間、裝置、音源、規則、輸出、混音、回傳診斷與關閉。Run 沒有預設時限，並接受互動命令或命令 JSON。
- Windows 可執行檔需要系統管理員權限。選用的提高權限登入啟動預設為關。明確的防火牆允許、重新整理與移除，只管理本可執行檔針對本地子網路的傳入 TCP/UDP 規則。

### 選用虛擬回傳

- 具備回傳能力的房間服務，為每台提出請求的電腦提供一名普通虛擬成員。該成員透過普通對等協定返回這台電腦的原始音訊，返回範圍限於該電腦自己的原始音訊。它不需要音訊裝置或播放緩衝區。
- Start 以可見方式啟用並儲存所需的房間方向，同時保留麥克風發佈與輸出選擇。Stop 移除該成員，並保留普通的已儲存規則。
- 封包往返，以及從擷取到回傳接收，這兩類觀測有已命名的邊界。這些觀測不代表從發聲到入耳的延遲。此項仍然是選用的正常使用診斷。

## 剩餘收尾與證據

目前原始碼接通了設定移轉、卡片編輯、逐路狀態、按需擷取、資源回收、平滑處理與同時使用的 IPv4/IPv6 路徑。原始碼中的命令、版本與多語言使用說明已對齊。OpenWrt 整合 現採用本應用程式的獨立原生套件、GL Tools 頁與自有 CGI，並使用官方管理員工作階段；已退役的閘道控制器保持停用。普通更新保留組態以及實際的執行/開機啟動意圖，代理/網路後端保持不變。[OpenWrt 管理](../services/openwrt-admin/README.zh-TW.md)記錄本機命令邊界。

所有者操作全部實際測試。沒有新的明確請求時，不要啟動應用程式、不要自動化介面、不要執行測試，也不要探測真實的音訊或網路裝置。必要的、有針對性的編譯與原始碼檢查仍是實作輔助。會帶來後果的功能或架構選擇，在依賴它們的實作之前報告。

框架隨附的應用程式圖示與系統匣圖示仍然保留；專用圖示尚無獲准設計。尚未約定 Windows 安裝程式。現有可攜式封存是歷史候選，原始碼組裝之後需要明確取代。首次使用與延遲邊界記錄在 [FIRST-USE.zh-CN.md](FIRST-USE.zh-CN.md) 與 [LATENCY.zh-TW.md](LATENCY.zh-TW.md)。

macOS 與 Arch 適配跟隨 Windows。SonoBus 是設計與程式碼參考。互通位於範圍之外。錄音、快速鍵、網際網路/NAT 執行、加密以及自訂 Windows 驅動程式開發，位於已約定的 Windows 範圍之外。
