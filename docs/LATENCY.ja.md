# オーディオ遅延と生存期間の境界

目的は、取得した PCM 精度を保ちつつ、避けられる遅延を最小にすることである。固定の遅延目標はない。経路全体で有用な用語は、キャプチャデバイス／Windows の取得周期、キャプチャの受け渡しとパケット化、片道のネットワーク配送、受信側の予備と変換、ネイティブ出力のパディングとデバイス遅延である。用語は重なりうる。それぞれの独立した上限を足して、観測結果にはできない。

## ネイティブキャプチャと出力

システム音は、選んだレンダーエンドポイントの共有ループバック経路を使う。WASAPI の `InitializeSharedAudioStream` はループバックフラグを受け付けない。そのためこの経路は、古典的な共有初期化を使う。マイク／出力経路は、対応する共有の低周期機能を試み、フォールバックを記録する。実際の周期、バッファ、ネイティブ形式が、開いたエンドポイントを述べる。要求した最小値は、達成した周期ではない。

受信者がなく、ローカルモニタもないとき、ネイティブキャプチャは閉じる。ピアコンタクト、許可、keepalive は活動したままである。新しい受信者は、音源役割の需要を通じてキャプチャを起こせる。そのとき新しいネイティブエポックはまだない。PCM を送る前に、そのエポックを確認する。これは最初の音にデバイス起動時間を足し、既存のピア接続は残す。

## 受け渡し、配送、再生

キャプチャは、より大きな人工ブロックを満たすのを待たず、取得したフレームを渡す。フレーム上限はブロックを拘束する。パケット化タイマーではない。キャプチャブロックが、ネイティブ周期に基づく予算より古いと捨てられる。パケットサイズは有界のままである。受信側は、古い音を加速して追いつかせない。

各出力は、クロックとレンダラを 1 つ持つ。各音源／出力のタイムラインは、自分のコンバータと配送予備を持つ。ネイティブエンドポイントのオーナーは、固定ガードなしで汎用レンダラを起動し、その後、実際の音源ブロック周期、出力周期を音源フレームへ換算した値、最近の配送ギャップからガードを導く。2 つの短い観測窓は、過去のジッタピークが期限切れになる余地を与える。この予備は準備した窓に有界であり、変わったときは現在のタイムラインを再プライムできる。汎用の `TimingPolicy::provisional()` 定数は、本番エンドポイントが固定で足す遅延ではない。

変換は入力の先読みを必要とし、準備済みコンバータの出力遅延を持つ。ネイティブ出力のパディングは、ソフトウェア提出のあとのさらなる境界である。レンダラは期限切れの滞留を捨て、途絶のあと現在の音を再プライムする。ゲイン／ミュート／回復は、既に期限の来た出力フレームの中で、約 2ms の短い振幅ランプを使う。追加のオーディオキューは作らない。取り消された方向は直ちに閉じる。切り離した完全な音源ウィンドウ／コンバータは、冷たいルーティング境界で解放する。入口の識別／エポック検査は、古いデータを拒む。

## 仮想リターンの観測

パケット往復は、元パケットのローカル送信から、ルータ経由の対応するリターン受信までを測る。キャプチャからリターン受信までは、プロセスが知るローカル取得／受け渡しの年齢も含む。どちらの観測も、最終ネイティブ出力、ヘッドフォン DAC、空気伝搬遅延を含まない。リターン仮想ピアは、キャプチャ、再生、リサンプリング、ミキシングを行わない。通常のオーディオは、なおピア間を直接届く。ルータリターンは、明示的な任意診断経路である。

音源／経路のカウンタと出力フェーズは、ソフトウェアの進捗と誤りを示す。聞こえる出力を証明しない。実際の利用と遅延テストは所有者が操作する。本文は、追加の物理検証ゲートを含意しない。
