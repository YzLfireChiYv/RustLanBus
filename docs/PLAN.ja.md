## 目的と完了の境界

複数の LAN コンピュータから原音を集め、ヘッドフォンまたはスピーカーに接続した Windows コンピュータへ届ける。取得時に得られる実質的な PCM 精度を保ち、避けられる遅延を最小にする。必要なクロック補正、ミキシング、宛先スピーカーへの適応は、再生の中で明示的に行う部分である。固定したミリ秒の目標はない。

ソースは、共有コントローラを通じて、合意した機能をつなぐ。2026-10-26 の仕上げ作業は、有効な設定バンドルと移行、カードの CRUD、経路ごとの正直な状態、アイドル時のキャプチャ停止、資源の退役、滑らかなゲイン／回復の境界、同時の IPv4／IPv6 経路を含む。範囲を絞ったコンパイルは実装を支える。所有者は、起動、インターフェース、オーディオ、ネットワークの実際のテストをすべて行う。現在のビルドやアーカイブは、製品全体の完了を確立しない。歴史的アーカイブは、本バッチより前である。

## アプリケーションの構造

- Tauri 2 は、Windows デスクトップのシェル、ウィンドウ、システムトレイを提供する。React 19 と TypeScript は、インストール済みの Microsoft Edge WebView2 ランタイムで、ローカルのインターフェースを描画する。ホスティングされたウェブサイトは不要である。
- 設定、ルーム、ルール、キャプチャ、伝送、クロック、再生は Rust が持つ。オーディオバッファは JavaScript を通らない。
- デスクトップと正式なヘッドレス CLI は、同じ `RunningParticipant` コントローラとコマンドを使う。設定 1 つにつき、実行中の GUI または CLI インスタンスは 1 つである。CLI は、開いているデスクトップを遠隔操作しない。
- キャプチャ、ネットワーク配送、再生先は、それぞれ独立した所有を持つ。解決済みの出力デバイスごとに、再生オーナーとクロックは 1 つである。

## 合意した目標の振る舞い

### ルームとメンバー

- 1 つのアクティブルームは、複数の独立したメンバーを支える。各デバイスは自分の名前を出す。参加中は名前が固定される。
- Windows の作成者、または OpenWrt サービスが、ルームのディレクトリとピアのアドレスを供給する。Windows の作成者がルームを離れるか切り替えると、自分のコンタクトサービスを止める。主宰側の権限行列、キック／承認の層、自動の主宰移行はない。
- パスワードは、誤って入ることを防ぐ。オーディオの方向は直接 P2P である。コンタクトサービスを失ったあとでも、既に確立した直接オーディオは続き、ディレクトリの回復はバックグラウンドで進む。
- 保存済みカードと、発見したルームは別である。まず、一意で正確な名前を選ぶ。名前が重複するときは、明示入力した IP が一意に一致すればそれを使い、そうでなければ利用者が選ぶ。発見された名前がないときは、入力したアドレスを探り、返された名前が一致する必要がある。厳格な自動入場は、入力した名前と IP が対応することを求める。
- 直接アドレスが別のルーム名を報告するときは、訂正が必要な宛先の誤りである。バックグラウンド待機は、一時的な不在またはコンタクト失敗にだけ出す。自動ネットワーキングは両方のアドレスファミリをバインドし、ピアごとの健全な経路を保つ。インタフェースまたは明示アドレスの厳格な制限は、黙って別経路へは落ちない。明示的にループバックへバインドしたセッションは、既定でローカルアドレス入力になり、LAN の閲覧はしない。探索の失敗は、利用可能な TCP ディレクトリを止めない。探索は独立して回復する。明示的な探索の上書きは、与えられた範囲を保つ。
- 未知のルームへ成功して入ると、カードを保存する。探索は、省いた保存 IP を埋めない。再開すると、保存したルームの意図を戻す。明示的な Leave は、自動再入場を無効にする。

### 音源と方向

- 受信者がなく、ローカルモニタもないとき、実際のネイティブキャプチャは閉じる。ピア制御、keepalive、公開の意図は残す。既存の購読は、新しい接続を待たずにキャプチャを起こす。
- システム音とマイクは、独立した原音である。既定: システムの公開はオン、マイクの公開はオフ、ローカルモニタリングはオフ。
- システム音は、選んだ再生エンドポイントからのループバックキャプチャである。そのエンドポイントは、多くの場合インストール済みの仮想スピーカーである。別の物理出力が、ローカルモニタリングと受信オーディオを運ぶ。RustLanBus は設定を案内し、独自のカーネルドライバは供給しない。
- 既定ルールは、全員への送信を許し、誰からも受信しない。A から B へは、A が送信を許し、B が受信を選ぶ必要がある。選んでいない方向にはオーディオは乗らない。
- メンバーを聴取すると、その現在の音源と以後の音源を覆う。展開した制御は、音源の役割を閉じられる。ローカルモニタリングは、ルームのメンバーシップから独立している。通常のクライアントが公開するのは、ローカルの原音だけである。

### ルールと永続化

- 編集可能な JSON が、グローバルルールと、ルームごとのプロファイルを持つ。グローバルルールが先に走り、ルームルールが続く。あとから一致した代入は、指定したフィールドごとに独立して上書きする。
- 条件は、名前、IP、またはその両方を明示的に照合する。名前だけの操作は、同じ名前のデバイスすべてに及ぶ。IP や永続的なデバイス識別は推論しない。
- ルーム操作は、ルームルールを更新して保存する。音源の方向、出力先、部分的なミックス欄は、同じ明示範囲を保つ。
- インタフェースは、決定したルールの由来と、ファイルごとの保存済み、未確定、外部変更、書き込み失敗の状態を示す。外部の置き換えは残す。再読み込みはファイル編集を適用する。きれいなグローバルは、ルーム入場時にも再読する。
- カードは、共有オーナーを通じて編集と削除ができる。外部変更の改訂検査がある。アクティブなカードは、先に離れなければならない。
- 1 つの読みやすい JSON 設定バンドルは、未保存の変更を含む、有効なローカル／グローバル／ルーム値を書き出す。明示的な復元／コピーのインポートは、置き換えをプレビューし、ソースと宛先の改訂を調べ、復旧ディレクトリを残す。コピーは新しい識別を作り、ローカルのオーディオ／ネットワーク結びつきを消し、自動入場、モニタリング、ログイン意図を無効にする。Main ルートは残り、固定宛先は取り除かれて列挙され、固定宛先だけのルートは空のままである。
- 未保存のグローバルは、明示的な再読み込みまで、ルーム切り替えのあいだ有効なままである。離れるか切り替えると、見える警告のあと、未保存のルーム変更を捨てる。書き出しは、元のファイルを変えずに、未保存の値を救い出せる。明示的な終了は、未保存ファイルを示し、戻るか捨てるかを出す。

### 形式、再生、出力

- ネイティブ整数 PCM16/24/32 と F32/F64 は、精度とスピーカーマスクの記述子を共有する。伝送は、宣言された原表現を保つ。作業サンプルは F64 を使う。現在のメディア回線: RLC5/RLP5。ディレクトリ JSON version2 は、同一 UDP ポート上に有界の代替を載せる。ディレクトリ実装とリターン実装は、クライアントと揃えて更新する必要がある。それより前の開発用ピアも、揃って更新する。
- モノラル、ステレオ、一般的な 5.1/7.1 レイアウトに対応する。Microsoft が公開した係数が、既存のレンダラで対応先を適応する。未対応の組み合わせは、音源／出力ごとに問題を報告し、原伝送と他の出力は続く。
- 各音源は複数の出力へ送れる。`main` は、選んだ主デバイスに従う。固定エンドポイントの選択は固定のままである。欠けた固定デバイスは、フォールバックせず回復を待つ。同一エンドポイントのエイリアスは、一度だけ描画する。
- 各出力は、自分の音源フェーズ、デバイス／形式の誤り、レベル、過負荷を示す。送信済み／実行中の表示は、ソフトウェアの進捗を述べる。聞こえるハードウェア出力を主張しない。欠けた、または古いインタフェース更新は見える。
- 切り離した完全な DSP レーンは、冷たい制御境界で退役する。短いゲイン／ミュート／回復ランプは既存のレンダラを共有し、遅延した PCM キューを足さない。
- 同じ出力を共有する音源は、そこでミックスする。副次制御は、音源ゲイン、ミュート、ソロ、パン、マスター音量を提供し、レベル／過負荷の情報を伴う。任意のリミッタは既定オフである。逃した古いオーディオは捨て、回復後は現在の音へ戻る。

### インタフェース、CLI、Windows 統合

- ルームとメンバーが第一である。音源の詳細、出力ルーティング、ミックス、ルール、診断は第二である。初回利用は、ローカル構成とオーディオ経路の案内を含む。
- 通常のウィンドウにはタスクバーボタンがある。閉じると隠し、アプリケーションは動き続ける。システムトレイはウィンドウを戻し、Exit を出す。明示的な Exit は、バックグラウンドのオーナーを止める。
- 正式な CLI は、構成の作成／検査、ルーム、デバイス、音源、ルール、出力、ミックス、リターン診断、終了を扱う。Run に既定の時間制限はなく、人間向けコマンドまたはコマンド JSON を受け付ける。
- Windows の実行ファイルは管理者権限を必要とする。任意の昇格ログイン起動は既定オフである。明示的なファイアウォールの許可／更新／削除は、この実行ファイルの、ローカルサブネット向け着信 TCP/UDP 規則だけを扱う。

### 任意の仮想リターン

- リターンに対応したルームサービスは、要求するコンピュータごとに、1 人の通常の仮想メンバーを出す。通常のピアプロトコルで、そのコンピュータ自身の原音だけを戻す。オーディオデバイスも再生バッファも不要である。
- Start は、必要なルーム方向を見える形で有効にして保存し、マイク公開と出力選択は残す。Stop はメンバーを取り除き、通常の保存済みルールは残す。
- パケット往復と、キャプチャからリターン受信までの観測には、名前付きの境界がある。これらは、音が出て耳へ届く遅延を表さない。通常利用の任意診断のままである。

## 残る仕上げと証拠

現在のソースは、設定の移行、カード編集、経路ごとの状態、要求時のキャプチャ、資源の解放、平滑化、同時の IPv4/IPv6 経路をつないでいる。ソース内のコマンド、版、多言語の利用説明は整合している。OpenWrt の統合はアプリケーション自身のネイティブパッケージ、モジュール、管理ページを対象とし、既存の認証済みゲートウェイ入口を使う。ソース変更だけでは、ルータのプロセスや共有ネットワーク設定は変化しない。構成要素の境界は[アーキテクチャ](ARCHITECTURE.md)を参照。

所有者は実際のテストをすべて操作する。新しい明示的な依頼がなければ、アプリケーションを起動せず、インターフェースを自動化せず、テストを実行せず、実在のオーディオ／ネットワーク機器も探らない。必要な、範囲を絞ったコンパイルとソース点検は、実装の助けのままである。結果を伴う機能またはアーキテクチャの選択は、それに依存する実装の前に報告する。

フレームワークのアプリケーション／トレイアイコンは残る。専用アイコンに承認されたデザインはない。Windows インストーラは合意されていない。既存のポータブルアーカイブは歴史的候補であり、ソース組み立てのあと明示的な置き換えを必要とする。初回利用と遅延の境界は [FIRST-USE.md](FIRST-USE.md) と [LATENCY.ja.md](LATENCY.ja.md) に書いてある。

macOS と Arch の適応は Windows に続く。SonoBus は設計とコードの参照である。相互運用は範囲の外である。録音、ホットキー、インターネット／NAT 運用、暗号化、独自 Windows ドライバ開発は、合意した Windows 範囲の外である。
