## 目的与完成边界

把若干局域网计算机上的原始音频汇集到一台连接耳机或扬声器的 Windows 计算机。保留采集时可获得的有效 PCM 精度，并尽量降低可避免的延迟。必要的时钟校正、混音与目标扬声器适配，是播放中的明确组成部分。没有固定的毫秒目标。

源码通过共享控制器连接已约定的功能。2026-10-26 的收尾工作包括生效设置包与迁移、卡片的增删改查、按路由如实反映状态、空闲时关闭采集、资源退役、平滑的增益/恢复边界，以及同时使用的 IPv4/IPv6 路径。有针对性的编译支持实现；所有者执行全部实际的启动、界面、音频与网络测试。当前任何构建或归档都不能确立整套产品完成。历史归档早于本批更新。

## 应用结构

- Tauri 2 提供 Windows 桌面外壳、窗口与系统托盘。React 19 与 TypeScript 在已安装的 Microsoft Edge WebView2 运行时中渲染本地界面。不需要托管网站。
- Rust 负责配置、房间、规则、采集、传输、时钟与播放。音频缓冲区不经过 JavaScript。
- 桌面与正式的无界面 CLI 使用同一个 `RunningParticipant` 控制器与同一套命令。一份配置对应一个正在运行的 GUI 或 CLI 实例。CLI 不远程控制已经打开的桌面。
- 采集、网络送达与播放目标拥有各自独立的所有权。每个已解析的输出设备有一个播放执行单元与一个时钟。

## 约定的目标行为

### 房间与成员

- 一个活动房间支持多名独立成员。每台设备提供自己的名称，加入期间名称固定。
- Windows 创建者或 OpenWrt 服务提供房间目录与对等端地址。Windows 创建者离开或切换房间时，停止自己的联络服务。没有主持端权限矩阵、踢出/审批层或自动主持端迁移。
- 密码防止误入。音频方向是直接 P2P。联络服务丢失后，已经建立的直接音频继续，目录恢复在后台进行。
- 已保存的卡片与已发现的房间彼此分开。首先选择唯一的精确名称。名称重复时，显式输入的 IP 能唯一匹配则使用该 IP，否则由用户选择。没有发现该名称时，对输入的地址进行探测，返回的名称必须匹配。严格的自动进入要求输入的名称与 IP 相互对应。
- 直接地址若报告另一个房间名称，这是需要纠正的目标错误。后台等待只提供给暂时缺席或联系失败。自动组网同时绑定两个地址族，并保持每条对等路径中健康的那一条。严格限制网卡或显式地址时，不会悄悄改走其它路径。显式绑定到环回的会话默认进入本地地址输入，不进行局域网浏览。发现失败不会中止可用的 TCP 目录；发现会独立恢复。显式的发现覆盖保留其所提供的范围。
- 成功加入未知房间会保存一张卡片。发现从不会填入已省略的已保存 IP。再次打开时恢复已保存的房间意图。显式 Leave 禁用自动再次进入。

### 音源与方向

- 没有接收方、也没有本机监听时，实际的原生采集会关闭，同时保留对等控制、keepalive 与发布意图。已有的订阅会唤醒采集，无需等待新的连接。
- 系统声音与麦克风是相互独立的原始音源。默认：系统发布开，麦克风发布关，本机监听关。
- 系统声音是对所选播放端点的环回采集，该端点通常是已安装的虚拟扬声器。单独的物理输出承载本机监听与接收到的音频。RustLanBus 引导设置，不提供定制内核驱动。
- 默认规则允许向所有人发送，并且不从任何人接收。从 A 到 B 需要 A 允许发送，并且 B 选择接收。未选择的方向不传送音频。
- 收听一名成员时，覆盖该成员当前与此后的音源。展开的控件可以关闭某个音源角色。本机监听独立于房间成员身份。普通客户端所发布的内容限于本地原始音频。

### 规则与持久化

- 可编辑的 JSON 存放全局规则，以及每个房间一份配置档。全局规则先运行，房间规则随后运行。较后的匹配赋值按每个已指定字段分别覆盖。
- 条件显式匹配名称、IP 或两者。仅按名称的操作会影响所有同名设备。不会推断 IP 或持久设备身份。
- 房间操作更新并保存房间规则。音源方向、输出目标与部分混音字段保持同一显式范围。
- 界面显示决定性规则的来源，以及每个文件的已保存、待处理、外部更改与写入失败状态。外部替换予以保留。重新载入会应用文件编辑。无未保存改动的全局规则在进入房间时也会重新读取。
- 卡片可通过共享所有者编辑与删除，并带有外部更改的修订检查；当前活动卡片必须先离开。
- 一份可读的 JSON 设置包导出当前生效的本地/全局/房间值，包括尚未保存的改动。显式的还原/复制导入会预览替换内容，检查源与目标修订，并保留一个恢复目录。复制会创建新身份，清除本地音频/网络绑定，并关闭自动进入、监听与登录意图；Main 路由保留，固定目标被移除并列出让你重新指定，仅含固定目标的路由保持为空。
- 未保存的全局规则在房间切换之间保持有效，直到显式重新载入。离开或切换房间时，在可见警告之后丢弃未保存的房间更改。导出可以救出尚未保存的值，且不改写它们的原文件。明确退出会标出尚未保存的文件，并提供返回或丢弃。

### 格式、播放与输出

- 原生整数 PCM16/24/32 与 F32/F64 共用一套精度与扬声器掩码描述符。传输保留所声明的原始表示。工作采样使用 F64。当前媒体线路：RLC5/RLP5。目录 JSON version2 在同一 UDP 端口上携带有界的地址备选。目录实现与回传实现都需要与客户端一并更新。更早的开发中对等端需要一并更新。
- 支持单声道、立体声以及常见的 5.1/7.1 布局。Microsoft 已发布的系数在现有渲染器中适配受支持的目标。不受支持的组合按音源/输出报告问题，原始传输与其它输出继续。
- 每个音源可以送往多个输出。`main` 跟随所选的主设备。固定端点选择保持固定。缺失的固定设备等待恢复，不进行回退。同一端点的别名只渲染一次。
- 每个输出显示自己的音源阶段、设备/格式错误、电平与过载。已提交/正在运行的指示描述软件进度；它不声称硬件已经发出可听见的声音。界面更新缺失或过期时可见。
- 已脱离的完整 DSP 通道在冷控制边界退役。短暂的增益/静音/恢复斜坡共用现有渲染器，不增加延迟的 PCM 队列。
- 共用一个输出的音源在该输出上混音。次级控件提供音源增益、静音、独奏、声像与主音量，并带有电平与过载信息。可选限制器默认为关。错过的旧音频被丢弃，恢复之后回到当前声音。

### 界面、CLI 与 Windows 集成

- 房间与成员是首要内容。音源详情、输出路由、混音、规则与诊断是次要内容。首次使用包含本地配置与音频路由引导。
- 常规窗口带有任务栏按钮。关闭会隐藏窗口，应用程序继续运行。系统托盘恢复窗口并提供“退出”。明确选择“退出” 停止后台执行单元。
- 正式 CLI 覆盖配置创建与检查、房间、设备、音源、规则、输出、混音、回传诊断与关闭。Run 没有默认时限，并接受交互命令或命令 JSON。
- Windows 可执行文件需要管理员权限。可选的提升权限登录启动默认为关。显式的防火墙允许、刷新与移除，只管理本可执行文件针对本地子网的入站 TCP/UDP 规则。

### 可选虚拟回传

- 具备回传能力的房间服务，为每台提出请求的计算机提供一名普通虚拟成员。该成员通过普通对等协议返回这台计算机的原始音频，返回范围限于该计算机自己的原始音频。它不需要音频设备或播放缓冲区。
- Start 以可见方式启用并保存所需的房间方向，同时保留麦克风发布与输出选择。Stop 移除该成员，并保留普通的已保存规则。
- 数据包往返，以及从采集到回传接收，这两类观测有已命名的边界。这些观测不代表从发声到入耳的延迟。此项仍然是可选的正常使用诊断。

## 剩余收尾与证据

当前源码接通了设置迁移、卡片编辑、逐路状态、按需采集、资源回收、平滑处理与同时使用的 IPv4/IPv6 路径。源码中的命令、版本与多语言使用说明已对齐。OpenWrt 集成 现采用本应用的独立原生软件包、GL Tools 页与自有 CGI，并使用官方管理员会话；已退役的网关控制器保持停用。普通更新保留配置以及实际的运行/开机启动意图，代理/网络后端保持不变。[OpenWrt 管理](../services/openwrt-admin/README.zh-CN.md)记录本地命令边界。

所有者操作全部实际测试。没有新的明确请求时，不要启动应用程序、不要自动化界面、不要执行测试，也不要探测真实的音频或网络设备。必要的、有针对性的编译与源码检查仍是实现辅助。会带来后果的功能或架构选择，在依赖它们的实现之前报告。

框架自带的应用程序图标与托盘图标仍然保留；专用图标尚无获准设计。尚未约定 Windows 安装程序。现有便携归档是历史候选，源码组装之后需要明确替换。首次使用与延迟边界记录在 [FIRST-USE.zh-CN.md](FIRST-USE.zh-CN.md) 与 [LATENCY.zh-CN.md](LATENCY.zh-CN.md)。

macOS 与 Arch 适配跟随 Windows。SonoBus 是设计与代码参考。互通位于范围之外。录音、热键、互联网/NAT 运行、加密以及定制 Windows 驱动开发，位于已约定的 Windows 范围之外。
