# 音訊延遲與生命週期邊界

目標是保留擷取到的 PCM 精度，同時盡量降低可避免的延遲。沒有固定的延遲指標。有用的整條路徑用語包括：擷取裝置/Windows 的擷取節奏、擷取交接與打包、單向網路送達、接收端儲備加轉換，以及原生輸出填充與裝置延遲。這些用語可以重疊；各自的獨立上限不能相加後當作一次觀測結果。

## 原生擷取與輸出

系統聲音使用所選彩現端點的共享迴路路徑。WASAPI 的 `InitializeSharedAudioStream` 不接受迴路旗標，因此這條路徑使用經典的共享初始化。麥克風/輸出路徑會嘗試受支援的共享低週期設施，並記錄回退。實際週期、緩衝區與原生格式描述已開啟的端點；請求的最小值不等於已經達到的週期。

沒有接收端、也沒有本機監聽時，原生擷取會關閉。對等聯絡、授權與 keepalive 保持活動。新的接收端可以透過音源角色需求喚醒擷取，此時新的擷取代次尚未建立。PCM 傳送之前會確認該代次。這會把裝置啟動時間加到第一聲，同時保留已有的對等連線。

## 交接、送達與播放

擷取交出已取得的幀，不等待填滿更大的人工塊。幀上限約束塊的大小；它不是打包計時器。擷取塊若超過按其原生週期計算的預算，就會被丟棄。封包大小保持有界，接收端不會加速過時聲音來追趕。

每個輸出擁有一個時鐘與一個渲染器。每條音源/輸出時間線有自己的轉換器與送達儲備。原生端點執行單元啟動通用渲染器時不帶固定保護，隨後根據實際音源塊節奏、換算成音源幀的輸出週期，以及近期送達缺口，推導出保護值。兩個短觀察視窗允許過去的抖動峰值過期。該儲備受已準備視窗約束，變更時可以重新填裝目前時間線。通用的 `TimingPolicy::provisional()` 常數不是生產端點固定附加的延遲。

轉換需要輸入預讀，並帶有已準備轉換器的輸出延遲。原生輸出填充是軟體提交之後的又一道邊界。渲染器丟棄過期積壓，並在中斷之後重新填裝目前聲音。增益/靜音/復原使用約 2ms 的短幅度斜坡，作用在已經到期的輸出幀上；它不額外建立音訊佇列。被撤銷的方向立即關閉。已脫離的完整音源視窗/轉換器在路由更新階段釋放；入口身分/代次檢查會拒絕過時資料。

## 虛擬回傳觀測

封包往返測量的是：原始封包從本機傳送，經路由器，到對應回傳接收。從擷取到回傳接收，還包含行程已知的本機擷取/交接年齡。這兩類觀測都不包含最終原生輸出、耳機 DAC 或空氣傳播延遲。回傳虛擬對等端不進行擷取、播放、重新取樣或混音。普通音訊仍然在對等端之間直接傳送；路由器回傳是一條明確的、選用的診斷路徑。

音源/路由計數與輸出階段標識軟體進度與錯誤。它們不能證明已經發出可聽見的聲音。真實使用與延遲測試由所有者操作；本文不隱含額外的物理驗證門檻。
