RustLanBus は、LAN 上のコンピュータのあいだで原音を共有する。主な用途は、複数デバイスの音を、ヘッドフォンまたはスピーカーへ接続した 1 台の Windows コンピュータに集めることである。取得した PCM 精度を保ち、避けられる遅延を最小にする。再生では、クロック補正、ミキシング、スピーカー適応を明示的に行う。

Windows が最初のプラットフォームである。デスクトップと正式な CLI は、1 つの Rust コントローラを共有する。2026-10-26 のソースは、完全なカード／設定管理、需要駆動のキャプチャ、音源／出力の診断、同時の IPv4／IPv6 経路を加える。製品の実装と、所有者が行うテストは、分けて記録する。以前のポータブルアーカイブは歴史的な候補のままであり、本バッチの変更を含まない。[現在の製品計画](docs/PLAN.ja.md)と[アーキテクチャ](docs/ARCHITECTURE.md)を参照。

公開ソース: [YzLfireChiYv/RustLanBus](https://github.com/YzLfireChiYv/RustLanBus)。公開の履歴には、レビュー済みのスナップショットが含まれる。私的な調査と配置の記録は、分けたままである。SonoBus は設計とコードの参照である。RustLanBus は独自のプロトコルを使い、SonoBus とは相互運用しない。

## デスクトップとオーディオ設定

デスクトップは **Tauri 2、React 19、TypeScript** を使う。描画は、インストール済みの Microsoft Edge WebView2 ランタイムがローカルで行う。共有コントローラ、キャプチャ、ネットワーク、再生は Rust が持つ。オーディオは JavaScript を通らない。

ポータブルな Windows アーカイブを展開し、`RustLanBus.exe` を実行する。Windows は管理者権限を求める。ウィンドウにはタスクバーボタンがある。**X** はウィンドウを隠し、バックグラウンドのオーディオは続く。システムトレイのアイコンをクリックするとウィンドウが戻り、そのメニューから **Exit** を選ぶとプログラムが止まる。ウィンドウにも、明示的な終了操作がある。

仮想の **再生** エンドポイントを、システムのループバック音源として選ぶ。Windows で、各アプリケーションの音をそこへ送る。物理的なヘッドフォンまたはスピーカーを、RustLanBus の出力として選ぶ。これらのエンドポイントを分けておくと、受信したオーディオは原音のキャプチャに入らない。仮想エンドポイントは、別にインストールしたコミュニティドライバから来る。RustLanBus は独自のカーネルドライバを供給しない。アプリ内ガイドは、公式プロジェクトと Windows の設定ページを開く。[初回利用ガイド](docs/FIRST-USE.md)に従う。任意の FxSound 仮想デバイスを使うときは、終了してからルーティングを変える順序を含む。

Windows 上でルームを作るか、Windows／OpenWrt のルームサービスに参加する。サービスはピアのアドレスを紹介する。オーディオはメンバー間を直接届く。パスワードは、誤って入ることを防ぐ。コンタクトサービスが使えなくなっても、既にある直接オーディオは続く。既定では、1 つのインスタンスが IPv4 と IPv6 の両方をバインドし、通常のハンドシェイクで候補ペアを探る。健全な経路は選ばれたままである。詳細設定では、ネットワークインタフェースまたはローカルアドレスを厳格に制限できる。制限したネットワークが使えないときは待ち、黙って別経路へは落ちない。

既定は **全員へ送信し、誰も聴取しない。システム音はオン、マイクはオフ、ローカルモニタリングはオフ** である。聴くメンバーを選ぶ。聴取の対象は、そのメンバーの現在の音源と、以後の音源である。展開した詳細には、音源ごとの制御がある。音源は 1 つの出力を共有でき、各音源は複数の出力へ送れる。

グローバルな JSON ルールと、ルームごとの JSON ルールは、名前、IP、またはその両方を明示的に照合する。あとから一致したフィールドが優先される。ルームルールは、グローバルルールの後に実行される。名前だけの制御は、同じ名前のデバイスすべてに及ぶ。保存の失敗と、決定したルールは表示される。ファイルの編集は、再読み込みのとき、または次にルームへ入るときに適用される。探索は、保存時に省いた IP を埋めない。保存済みカードには編集と削除がある。アクティブなカードを削除する前に、そのカードから離れる。

ネイティブ整数の PCM16/24/32 と F32/F64 は、伝送の中で、それぞれ宣言された表現を保つ。作業バッファは F64 を使う。一般的なモノラル／ステレオと 5.1/7.1 のレイアウトには、スピーカーを考慮した割り当てがある。未対応の宛先は、音源／出力ごとに報告される。受信の需要がなく、ローカルモニタリングもないとき、ネイティブキャプチャは閉じる。公開の意図、P2P コンタクト、keepalive は残る。現在のメディアプロトコル: RLC5/RLP5。ディレクトリプロトコル: JSON version2。同一 UDP ポート上に、有界のアドレス候補を載せる。それより前の開発用ピアは、揃って更新する必要がある。

任意のログイン時起動は、既定でオフである。明示的な Windows の操作で、昇格したログイン時タスクを登録できる。または、このプログラムについて、ローカルサブネットからの着信 TCP/UDP を許可できる。これらの操作はオーディオドライバをインストールせず、ファイアウォールのグローバルな既定も変えない。実行ファイルを移すと、明示的な再登録が必要になることがある。インタフェースは実際の登録を示し、修復と削除を提供する。

GL SDK4 の OpenWrt 対象では、RustLanBus は独立したネイティブパッケージと Tools ページを持ち、公式の管理者セッションを使う。その CGI と短命の管理コマンドは、コンタクトデーモンが停止しているあいだも動作する。通常のアプリケーション保守は、旧来のゲートウェイコントローラを必要とせず、プロキシ／ネットワークのバックエンドも変えない。[OpenWrt 管理](services/openwrt-admin/README.ja.md)を参照。

## 設定と復旧

データは Windows のユーザーディレクトリに置かれる。**アプリケーションと設定** は、現在の構成と GUI／コアのビルド識別を示し、別の構成を開くこと、1 つの読みやすい JSON 設定バンドルを書き出すこと、インポートのプレビューと宛先の選択を扱う。書き出しは、未保存の値を含む、現在有効な設定を入れ、元のファイルは変えない。ルームのパスワードを含むため、私的なバックアップと一緒に保管する。

**このコンピュータへ復元** を選ぶと、識別とローカルの結びつきを残す。**新しいデバイスへコピー** を選ぶと、新しい識別を作り、ローカルのキャプチャ／出力デバイスを再確認する。コピーモードは、自動入場、モニタリング、ログイン時起動を無効にする。記号的な Main ルートは残し、固定エンドポイントの宛先は取り除いて再指定用に列挙する。固定宛先だけのルートは空のままである。プレビューは、宛先の置き換えと、残す復旧ディレクトリを示す。破損したカードは、設定バンドルの中で元のバイトとして残る。

ウィンドウを閉じると隠れる。明示的な終了は、未保存のファイルを列挙し、戻るか、意図して捨てるかを選べる。構成のインポートや切り替えも、未確定の変更を示す。人が読める JSON ファイルは、プログラムの外でも編集できる。それらの編集を適用するには再読み込みを使う。

## ヘッドレス Windows 入口

CLI とデスクトップは、同じ Rust コントローラを使う。設定 1 つにつき、実行中のインスタンスは 1 つである。昇格した端末からエンジンを実行する。リダイレクトされた入力と出力は保たれる。

```text
rustlanbus-engine participant --help
rustlanbus-engine participant init local.json --name Headphones --bind 0.0.0.0:0
rustlanbus-engine participant inspect local.json
rustlanbus-engine participant cards local.json
rustlanbus-engine participant run local.json --stdin --json
```

`--stdin` がないとき、Run は中断されるまで、または明示的な `--seconds N` の上限まで、動作したままである。`--stdin` があるとき、EOF で正常に停止する。人間向けのコマンドとコマンド JSON は、ルーム、デバイス、音源、ルール、出力、ミックス、ネットワーク選択、設定／カード管理を扱う。`settings pending` は未保存ファイルを列挙する。`settings export PATH` は、現在有効な設定を書き出す。オフラインの `settings preview` と `settings import` は、明示的なモード、ソース改訂、置き換えの確認を必要とする。コマンドのヘルプを見る。正式な入口は、生の内部診断コマンドを拒否する。ルームの外では `name "Headphone PC"` で名前を変える。参加中は、共有コントローラが改名を止める。JSON モードは、タグ付きの snapshot/result/error レコードを stdout へ書く。ヘルプは stderr へ出る。オフラインの検査は、オーディオオーナーを起動しない。

次の対話ルールの例は、メンバーを聴取し、そのマイクを除く。

```text
rule room --match name Music --listen on
rule room --match name Music --source microphone --listen off
```

出力の選択は、受信とは独立である。`main` は、選んだ主出力に従う。固定エンドポイントは、切断されているあいだ回復を待つ。出力リストが空のとき、その範囲では受信を保ち、ローカル再生を止める。

リターンに対応したルームサービスでは、`return start` が仮想メンバーを作り、このコンピュータ自身の原音を戻す。`return stop` はそのメンバーを取り除く。Start は、必要な通常のルーム方向を有効にして保存する。タイミングの報告は、パケットの往復と、キャプチャからリターン受信までを、物理的な聴取の遅延から区別する。[遅延の境界](docs/LATENCY.ja.md)は、ネイティブ周期、有界キュー、配送予備、変換を説明する。パケット RTT を総遅延としては扱わない。

## ビルドとソースの配置

実際のアプリケーション、インターフェース、オーディオ、ネットワーク、テストの実行は、所有者が行う。ソースの点検と、範囲を絞ったビルド確認は、実装を支える。それらが確立するのは、ビルド状態だけである。

```powershell
cargo check -p rustlanbus-engine -p rustlanbus-ui --offline
cd apps/desktop
npm ci
npm run build
```

`scripts/build-windows.ps1 -Build` は、使い方、ライセンス、ハッシュを添えて、新しいポータブル GUI/CLI ディレクトリを組み立てる。ドライバはインストールしない。起動やファイアウォールの設定は変えない。ソースも公開しない。

- `crates/rlb-model/`: 識別、PCM 精度、スピーカー位置。
- `crates/rlb-peer/`: ピアプロトコルと公開の契約。
- `apps/engine/`: 共有の参加者コントローラと、Windows オーディオランタイム。
- `apps/desktop/`: Tauri のシェルと React のインターフェース。
- `services/contactd/`: ルームのコンタクトと、任意の仮想リターンへの対応。
- `crates/rlb-return/`: 通常の仮想リターン参加者。
- `apps/peer-lab/` と `apps/audio-lab/`: 明示的な開発用の診断。
