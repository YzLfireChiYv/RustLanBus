`rustlanbus-openwrt-admin` は、RustLanBus のネイティブパッケージ向けの、短命なローカル管理コマンドである。オーディオ／コンタクトデーモンは、別プロセスのままである。そのデーモンを停止しても、構成と管理へのアクセスは残る。

本アプリケーションは、UCI ファイル `/etc/config/gw_app_rustlanbus` を 1 つ、既存の procd サービス、および自前の GL Tools ページ／CGI を持つ。管理は、公式の GL 管理者セッションを使う。追加の管理リスナー、アカウント、ゲートウェイコントローラ依存、私的なアプリケーション導入プラットフォームはない。

配置アダプタは、認証、プロセスをまたぐネイティブロック、リクエスト長の上限、CGI のタイムアウトを供給する。本コマンドが受け付けるのは `status` または `request` だけである。後者は、標準入力から有界 JSON を読む。ローカルコマンドを出すとき、呼び出し側は同じアプリケーションロックを持っていなければならない。

## 契約

status は、構成を、実際のネイティブサービス、プロセス、準備完了状態から分けて報告する。ランタイムファイルは、プロセスの PID、開始 ticks、実行ファイル、固定引数と一致しなければならない。非アクティブなサービスでも、構成はできる。パスワードは `password_set` だけで表す。

JSON リクエストは `action` を持つ: `start`、`stop`、`restart`、`enable`、`disable`、または `save`。save は、直近の status の `revision` と、`config` オブジェクトも必要とする: `enabled`、`bind`、`return_bind`、`room_name`、`password_action`、`password`。`password_action` は、保存値を明示的に保持、置換、または消去する。未知のフィールドは拒否される。`return_bind` が空、または省略されているときは、任意のリターンホストを無効にする。ソケット欄は、明示的な IP と、0 でないポートを使う。

`enabled` は起動時の好みである。start/stop はそれを変えない。enable は起動時スタートを登録し、サービスは起動しない。disable は停止し、登録を外す。save のとき起動時の好みだけを変えても、一時的な実行は止めない。ルーム／パスワード／バインドの変更を保存すると、すでにアクティブな本アプリケーションだけを再起動する。失敗した変更は、元の構成バイトとランタイムの意図を戻そうとする。外部のファイル変更は残し、不完全な復元は報告する。

## ネイティブのライフサイクルと範囲

通常パッケージの init は、自動起動のとき、その起動時の好みに従う。マネージャは、明示的な start/restart コマンドにだけ `RUSTLANBUS_TEMPORARY_START=1` を与える。制御されたネイティブアップグレードは、現在の構成と実際のランタイム／rc の意図を残し、`IPKG_NO_SCRIPT=1` で SDK の postinst だけを飛ばし、記録した意図を戻す。ネイティブの prerm は、本アプリケーションの旧プロセスをなお止めうる。復旧のために、互換のある以前の IPK と、構成のスナップショットを残す。

ネイティブの GL ビュー、CGI、procd レシピ、配置の記録は、ルータ統合リポジトリに属する。それらは、ベンダー既存の拡張点を使い、退役したゲートウェイコントローラの復活を必要としない。UI と聴取のテストは、所有者が操作する。本管理アダプタは、オーディオ回線とディレクトリプロトコルを変えない。
